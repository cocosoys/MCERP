# 06・前端定制与微前端

前端工程位于 `RuoYi-Vue2-master/`（基于 RuoYi-Vue2 3.9.2 / Vue 2.6 /element-ui 2.15 /vue-router 3 定制）。

## 1. 构建与同步



```
cd RuoYi-Vue2-master

npm install          # 首次

npm run build:prod   # 生产构建（输出 dist/）
```

构建后把 `dist/` **全量同步**到后端资源目录，再重新打 jar：



```
Copy-Item dist\\\* ..\src\main\resources\dist\ -Recurse -Force

cd ..

mvn -o clean package -DskipTests
```

> `dist/`
>
>  内必须包含 
>
> `__SOYS_CONTEXT__.js`
>
> （主插件契约注入点）。切勿手工删改该文件。

## 2. 生产关键配置

`vue.config.js`：



```
publicPath: process.env.NODE\_ENV === "production" ? "/web/plugins/MCERP/" : "/",
```

`.env.production`：



```
VUE\_APP\_TITLE = MCERP

VUE\_APP\_BASE\_API = '/prod-api'
```

> `VUE_APP_BASE_API`
>
>  是开发期代理用的相对前缀，生产请求地址由契约 
>
> `apiBase`
>
> （
>
> `/api`
>
> ）运行时决定。

## 3. 登录与鉴权前端



* 登录 / 登出 / 会话检查直接复用主插件 auth 端点（`/api/auth/*`）与 `soys-auth.js`：

  Bearer token 注入、401 统一跳登录页；

* MCERP 自身前端契约：


  * `GET /api/plugins/MCERP/auth/getInfo` → user/roles/permissions；

  * `GET /api/plugins/MCERP/auth/getRouters` → 当前用户可见路由树；

* 前端 `permission.js` 依据 `getRouters` 动态生成侧边栏与路由。

## 4. 微前端（wujie）与 iframe

### 4.1 主应用侧（MCERP）



* 菜单渲染时，按模块 `componentMode` 决定容器：


  * `WUJIE`（默认）：`WujieLink` 组件（无界微前端），name = 插件名（保活键）、url = 模块页面地址、

    props 传入 token 与微前端模式标记；

  * `IFRAME`：传统 iframe。

* TagsView 保活体系兼容两种模式（meta 带 mode 标记）。

* 主应用侧在菜单切换（url 变化）时通过 `$wujie.bus` 发出 `router-push` 事件，

  通知子应用内部跳转（不重载子应用）。

### 4.2 子应用侧（附属插件前端，如 SOYSHTTPOverMC-ERP）

wujie 模式需要子应用配合以下三点：



| 项             | 要求                                                                                                                                             |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| `publicPath`  | 生产构建改**绝对前缀**（如 `/web/plugins/<模块ID>/`），否则深层 URL 下 chunk 404                                                                                   |
| `router base` | history 模式 + `base` 运行时取自契约 `pageFullPrefix`                                                                                                   |
| 微前端生命周期       | `__WUJIE_MOUNT__` / `__WUJIE_UNMOUNT__`：mount 时读主应用传的 `props.path` 并 `router.push`；监听 `$wujie.bus` 的 `router-push` 事件做运行时路由同步；unmount 时解除监听防泄漏 |
| Layout / 登录页  | 微前端模式下剥离自身 Layout（空 Layout）、禁用自身登录页（同源已登录，由主应用统一鉴权）                                                                                            |

### 4.3 菜单切换路由同步

主应用 `WujieLink/index.vue` 中，当菜单切换（url 变化）时：



```
this.\$nextTick(() => {

&#x20; this.\$refs.wujie.bus.\$emit('router-push', this.props.path)

})
```

`props.path` 是当前菜单对应的子应用路由路径（如 `/erp/group`）。

若点击菜单后子应用停留在旧页面，优先排查此处是否已 emit。

### 4.4 wujie 沙箱中的 element-ui 弹层

wujie 沙箱中子应用 DOM 位于 shadowRoot，element-ui 的 popper 定位可能错位（如下拉跑到左上角）。

修复方向：在主应用 `WujieLink` 的 wujie 配置中注入 plugins（全局 CSS/JS），

强制 element-ui popper 定位基准正确（或按场景注入修复样式）。

## 5. 常见问题



| 现象                | 原因 / 解决                                                    |
| ----------------- | ---------------------------------------------------------- |
| 子应用白屏 /chunk 404  | 子应用 `publicPath` 未绝对化，或 router `base` 未设为 `pageFullPrefix` |
| 菜单切换子应用不跳转        | 主应用未 emit `router-push`，检查 `WujieLink/index.vue`           |
| 弹层（下拉 / 日期）定位错乱   | wujie 沙箱 popper 定位问题，注入修复 CSS/JS 或改用非 popper 组件            |
| 标题栏 logo 仍是 RuoYi | `src/assets/logo/logo.png` 未替换，重新构建同步 dist                 |
