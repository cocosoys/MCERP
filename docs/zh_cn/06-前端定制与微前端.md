# 06・前端定制与微前端

前端工程位于 `RuoYi-Vue2-master/`（基于 RuoYi-Vue2 3.9.2 / Vue 2.6 /element-ui 2.15 /vue-router 3 定制）。

## 1. 构建与同步



```
cd RuoYi-Vue2-master

npm install          # 首次

npm run build:prod   # 生产构建（输出 dist/）
```

构建后把 `dist/` **全量同步**到后端资源目录，再重新打 jar：



```
Copy-Item dist\\\* ..\src\main\resources\dist\ -Recurse -Force

cd ..

mvn -o clean package -DskipTests
```

> `dist/`
>
>  内必须包含 
>
> `__SOYS_CONTEXT__.js`
>
> （主插件契约注入点）。切勿手工删改该文件。

## 3. 登录与鉴权前端



* 登录 / 登出 / 会话检查直接复用主插件 auth 端点（`/api/auth/*`）与 `soys-auth.js`：

  Bearer token 注入、401 统一跳登录页；

* MCERP 自身前端契约：


  * `GET /api/plugins/MCERP/auth/getInfo` → user/roles/permissions；

  * `GET /api/plugins/MCERP/auth/getRouters` → 当前用户可见路由树；

* 前端 `permission.js` 依据 `getRouters` 动态生成侧边栏与路由。

## 4. 微前端（wujie）与 iframe

### 4.1 主应用侧（MCERP）



* 菜单渲染时，按模块 `componentMode` 决定容器：


  * `WUJIE`（默认）：`WujieLink` 组件（无界微前端），name = 插件名（保活键）、url = 模块页面地址、

    props 传入 token 与微前端模式标记；

  * `IFRAME`：传统 iframe。

* TagsView 保活体系兼容两种模式（meta 带 mode 标记）。

* 主应用侧在菜单切换（url 变化）时通过 **wujie 全局 `bus`**（`import { bus as wujieBus } from 'wujie'`）
  发出 `router-push` 事件，通知子应用内部跳转（不重载子应用）；详见 4.3。

### 4.2 子应用侧（附属插件前端，如 SOYSHTTPOverMC-ERP）

wujie 模式需要子应用配合以下三点：



| 项             | 要求                                                                                                                                             |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| `publicPath`  | 生产构建改**绝对前缀**（如 `/web/plugins/<模块ID>/`），否则深层 URL 下 chunk 404                                                                                   |
| `router base` | history 模式 + `base` 运行时取自契约 `pageFullPrefix`                                                                                                   |
| 微前端生命周期       | `__WUJIE_MOUNT__` / `__WUJIE_UNMOUNT__`：mount 时读主应用传的 `props.path` 并 `router.push`；监听 wujie 全局 `bus` 的 `router-push` 事件做运行时路由同步；unmount 时解除监听防泄漏 |
| Layout / 登录页  | 微前端模式下剥离自身 Layout（空 Layout）、禁用自身登录页（同源已登录，由主应用统一鉴权）                                                                                            |

### 4.3 菜单切换路由同步

主应用 `WujieLink/index.vue` 中，当菜单切换（url 变化）时：



```
import { bus as wujieBus } from 'wujie'

// url 变化后（$nextTick 内）
wujieBus.$emit('router-push', this.subPath)
```

要点：

* **必须用 wujie 全局 `bus`**（`import { bus } from 'wujie'`），不能用 `this.$refs.wujie.bus`：
  每个 wujie 实例的 `bus` 是各自独立的对象，子应用只在 `__WUJIE_MOUNT__` 里注册过一次监听，
  从 `$refs.wujie.bus` 发出的事件到不了那条监听，表现为"点菜单后子应用停在旧页面"。
* 发送的是 `this.subPath`（当前菜单相对该模块的路径，如 `/config/gateway/gw-config`），
  不是 `this.props.path`；`props.path` 只用于 mount 时的首次 `router.push`。
* 若点击菜单后子应用停留在旧页面，优先排查此处是否已 emit、以及是否误用了 `$refs.wujie.bus`。

### 4.4 wujie 沙箱中的 element-ui 弹层

wujie 沙箱中子应用 DOM 位于 shadowRoot，element-ui 的 popper 定位可能错位（如下拉跑到左上角）。

修复方向：在主应用 `WujieLink` 的 wujie 配置中注入 plugins（全局 CSS/JS），

强制 element-ui popper 定位基准正确（或按场景注入修复样式）。

### 4.5 关闭 wujie 的 URL 同步（`:sync="false"`）

`WujieLink` 的 wujie 配置显式关闭 `sync`：

* **现象**：`sync=true` 时 wujie 把子应用路径以子应用 name 为 key 写入主应用查询串
  （`?SOYSGiftLoft=/web/plugins/SOYSGiftLoft/...`），每切一次菜单追加一个 key，跨模块
  来回切换时 URL 参数无限增长，浏览器历史记录一并被污染。
* **决策**：`sync` 在本架构中是冗余能力——主应用的干净 URL 已唯一标识当前菜单；
  子应用挂载靠 `props.path`、切菜单靠全局 `bus` 的 `router-push`，刷新由父路由 +
  `props.path` 还原到同一页。
* **代价**：子应用内部、菜单树之外的临时跳转（如未注册为菜单的详情页）不会反映到
  地址栏，刷新会回到该菜单的默认页。当前所有子页面都走菜单注册，因此无实际影响。

### 4.6 头像上传（`POST /system/user/profile/avatar`）

* 前端 `views/system/user/profile/userAvatar.vue` 用 vue-cropper 裁剪后，把 **base64 data URL**
  放进 JSON 提交（`AvatarUploadVO#img`）；不使用 multipart——框架不解析 `multipart/form-data`。
* 后端 `ErpUserServiceImpl#avatar`：解码 data URL → 校验图片类型 → 落盘到
  `plugins/MCERP/avatar/` → 登记静态托管（`/web/plugins/MCERP/avatar/<文件名>`）→
  回填 `erp_user.avatar`（存根相对路径）。响应体在 `AjaxResult` 顶层额外带 `imgUrl`，
  前端据此立即刷新头像，无需重新拉取用户信息。
* 上传路径不存在时，启动钩子 `registerAvatarDirectory` 会批量登记已存在的头像目录。

### 4.7 菜单图标（sprite / 图片路径 / 插件 manifest）

侧边栏由 MCERP 宿主自己渲染（`layout/components/Sidebar/Item.vue` → 全局 `SvgIcon`），
所以图标的渲染能力由宿主定义，子应用自己的 `SvgIcon` 不参与。

> 完整接入步骤（放资源 → 写 manifest → 菜单引用 → 自检）见 04 - 扩展开发 §7。

宿主支持三种写法：

| 写法 | 渲染方式 | 约束 |
| --- | --- | --- |
| `user`、`form`（纯名字） | `<svg><use xlink:href="#icon-…">` | 名字必须存在于 `src/assets/icons/svg`，否则空白 |
| `/web/plugins/SOYSGiftLoft/icons/light_blue_bundle.png` | `<img>` 原色渲染，不做 mask 染色 | 只接受单个 `/` 开头的同源路径，扩展名限 png/jpg/jpeg/gif/webp/svg/ico/bmp/avif，可带 query |
| `img:<key>` | 先查所属插件的 `icons/manifest.json`，命中后按图片渲染 | 解析失败或图片 404 时回退 `form`，不留空白 |

manifest 契约（插件在自己的静态根即 `dist/` 根发布，宿主在登录后 `getRouters` 时按插件并行拉取，
3 秒超时、失败静默）：

```json
{
  "version": 1,
  "icons": {
    "pack": "icons/light_blue_bundle.png"
  }
}
```

* 值可以是相对插件根的路径，也可以是 `/web/plugins/<id>/...` 绝对路径；含 `..`、或绝对路径不在
  `/web/plugins/` 之下的会被拒绝。
* `img:` 的归属按菜单节点的 `component`（`wujie:/web/plugins/<id>/…` 或 `iframe:…`）判定；
  模块父节点自身没有组件时，按子树内唯一插件归属。
* 解析在 `utils/pluginIcons.js`，登录链路挂点 `store/modules/permission.js` 的 `GenerateRoutes`。
* 只为子树中真正使用 `img:` 的插件拉取 manifest；全部菜单都用 sprite 或直接图片路径时零请求，不增加登录耗时。
* 静态服务**不支持 HEAD**，探活只能用 GET；图标响应带 `Cache-Control: public, max-age=300`。
* 插件卸载或路径失效时，图片 `error` 会触发回退，不会出现空白或红叉。


## 5. 常见问题



| 现象                | 原因 / 解决                                                    |
| ----------------- | ---------------------------------------------------------- |
| 子应用白屏 /chunk 404  | 子应用 `publicPath` 未绝对化，或 router `base` 未设为 `pageFullPrefix` |
| 菜单切换子应用不跳转        | 主应用未 emit `router-push`，检查 `WujieLink/index.vue`           |
| 弹层（下拉 / 日期）定位错乱   | wujie 沙箱 popper 定位问题，注入修复 CSS/JS 或改用非 popper 组件            |
| 标题栏 logo 仍是 RuoYi | `src/assets/logo/logo.png` 未替换，重新构建同步 dist                 |
| 菜单图标空白 | icon 名不在宿主 sprite；或图片路径不符白名单（须单 `/` 开头 + 图片扩展名）；或插件 `icons/manifest.json` 404 |
