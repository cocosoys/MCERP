# 07・日志与运维

本文说明 MCERP 的操作日志与登录日志机制，以及常用运维手段。

## 1. 操作日志

### 1.1 记录内容

`erp_oper_log` 每条记录包含：



| 字段                    | 来源                                           |
| --------------------- | -------------------------------------------- |
| `title`               | 业务模块名（如 "用户管理"）                              |
| `businessType`        | 按业务动作文本推导：1 新增 / 2 修改 / 3 删除 / 0 其它          |
| `method`              | 业务动作（如 "新增用户"）                               |
| `requestMethod`       | HTTP 方法（GET/POST/PUT/DELETE），来自请求上下文         |
| `operName`            | 操作者玩家名（SOYS 凭证解析）                            |
| `operUrl`             | 请求地址（含前缀，如 `/api/plugins/MCERP/system/user`） |
| `operIp`              | 客户端 IP                                       |
| `operParam`           | 操作对象名（如新增的用户名）                               |
| `jsonResult`          | 返回结果文案（如 "新增成功"）                             |
| `status` / `errorMsg` | 状态（0 成功）与错误信息                                |
| `operTime`            | 操作时间（yyyy-MM-dd HH:mm:ss）                    |

### 1.2 实现机制



* 入口：`OperLogService.record(credential, title, business, target, result)`，

  由各 `*ServiceImpl` 在业务动作成功后调用（约 20 处）；

* **请求上下文**：主插件 `ApiRegistry.dispatch` 派发请求时把 `ApiRequestContext`

  绑定到当前 worker 线程（`ApiRequestContext.bind(ctx)`），`OperLogServiceImpl`

  经 `ApiRequestContext.current()` 免签名改动读取 `requestMethod / operUrl / operIp`；

* 写入失败仅打 warn 日志，不阻断主业务（日志横切）。

## 2. 登录日志

### 2.1 记录内容

`erp_logininfor` 每条记录包含：



| 字段          | 说明                                 |
| ----------- | ---------------------------------- |
| `userName`  | 登录玩家名                              |
| `ipaddr`    | 客户端 IP                             |
| `status`    | `0` 成功 / `1` 失败                    |
| `msg`       | 结果说明（成功 "登录成功"；失败带原因，如 "账号或密码错误…"） |
| `loginTime` | 登录时间                               |

### 2.2 实现机制



* `LoginLogListener`（Bukkit 事件监听器）旁路记账，挂主插件网关事件：


  * `GatewayLoginResultEvent`（**主通道**）：主插件 `AuthServiceImpl.login()`

    （弹窗登录成功 / 失败分支）与 `checkStatus()`（记住我 / 游戏 IP 自动登录成功）均 fire，

    携带 player /success/reason /ip → MCERP 写成功（status=0）或失败（status=1）；

  * `GatewayCredentialIssuedEvent`：`/soyshttp key` 命令签发凭证 → 成功记录（兜底）；

  * `GatewayAccessDeniedEvent`：仅记录登录链路（path 含 `/auth/`）的网关策略拒绝 → 失败记录（兜底）。

* 登录完全委托主插件 auth，本监听器只做旁路记账，写入失败打 warn 不影响网关。

### 2.3 前端查看



* 菜单「日志管理 → 操作日志」：列表 + 详情（含请求方法 / 地址 / IP / 返回结果）；

* 菜单「日志管理 → 登录日志」：成功 / 失败状态、原因、IP。

## 3. 运维命令



| 命令                 | 说明                                                      |
| ------------------ | ------------------------------------------------------- |
| `/mcerp reload`    | 重建 ERP 模块索引（以 `SoysExpansion.REGISTERED` 为准，清理残留 + 补登记） |
| `/mcerp list`      | 列出已登记模块（id + 显示名）                                       |
| `/soyshttp reload` | 主插件重载（会触发 `registerReloadHook`，MCERP 同步重建索引）            |

## 5. 故障排查线索



| 现象           | 排查方向                                                                                       |
| ------------ | ------------------------------------------------------------------------------------------ |
| 操作日志详情字段为空   | 主插件 jar 是否含 `ApiRequestContext.current()` 版本（≥ 1.4.0 改动）；请求是否走 `ApiRegistry.dispatch`      |
| 登录日志无成功 / 失败 | 主插件是否 fire `GatewayLoginResultEvent`（`AuthServiceImpl.login` 已接入）；`LoginLogListener` 是否已注册 |
| 日志写入失败       | 查看服务器 `latest.log` 中 `mcerp.operlog.write-failed` / `mcerp.logininfor.write-failed` warn   |
| 模块登记异常       | `/mcerp list` 查看已登记模块；`/mcerp reload` 重建索引                                                 |
