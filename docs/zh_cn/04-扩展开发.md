# 04・扩展开发（附属 ERP 模块）

MCERP 的核心扩展方式：**附属插件继承&#x20;**`McerpExpansion`**（它继承主插件&#x20;**`SoysExpansion`**）**，

只需覆写 ERP 声明钩子并调用一行 `register()`，即可自动完成 API 注册、页面托管、

数据初始化、菜单 / 路由登记 —— 即安即生效，卸载同步摘除。

## 1. 最小示例



```
package com.example.stock;

import com.github.cocosoys.mc.mcerp.ErpMenus;

import com.github.cocosoys.mc.mcerp.McerpExpansion;

import org.bukkit.plugin.java.JavaPlugin;

public class StockPlugin extends JavaPlugin {

    @Override

    public void onEnable() {

        // 一行注册：SoysExpansion 骨架自动执行端点登记 + 页面托管 + 数据初始化；

        // 本类 onRegister() 自动把模块（identifier/displayName/menus）登记进 MCERP ErpRegistry。

        if (!new StockExpansion().register()) {

            getLogger().warning("stock 注册失败（identifier 冲突 / bootstrap 未就绪）");

        }

    }

}

public class StockExpansion extends McerpExpansion {

    @Override

    public String getIdentifier() {

        return "stock"; // 唯一必填元信息：决定 /api/plugins/stock/\* 与 /web/plugins/stock/\* 前缀

    }

    @Override

    protected String displayName() {

        return "库存管理";

    }

    @Override

    protected int sortOrder() {

        return 20; // 模块在左侧菜单中的排序

    }

    @Override

    protected ErpMenus menus() {

        return ErpMenus.create()

            .dir("system", "系统管理", "system", d -> d

                .menu("user", "用户列表", "user").perm("soys.erp.user.list")

                .menu("group", "权限组列表", "lock"))

            .menu("home", "首页", "home").component("erp/home");

    }

    @Override

    protected String\[] dataRoots() {

        return new String\[]{"data"}; // 可选：释放 resources/data/\*.yml 作为初始化数据

    }

}
```

## 2. 可覆写钩子（全部可选，除 getIdentifier 外）



| 钩子                                                              | 默认                | 说明                                             |
| --------------------------------------------------------------- | ----------------- | ---------------------------------------------- |
| `getIdentifier()`                                               | —                 | **唯一必填**：模块标识，决定 API / 页面前缀                    |
| `displayName()`                                                 | identifier        | 左侧菜单显示的模块名                                     |
| `icon()`                                                        | null              | 模块图标                                           |
| `sortOrder()`                                                   | 0                 | 模块排序                                           |
| `permission()`                                                  | null              | 主菜单访问权限标识                                      |
| `homeUrl()`                                                     | null              | 无子菜单时的默认页地址                                    |
| `menus()`                                                       | null              | 声明式菜单树（`ErpMenus` DSL，与 `menusTable()` 二选一，优先） |
| `menusTable()`                                                  | null              | 直接返回 `List&lt;ErpMenuVO&gt;` 树（自行 new 拼接）      |
| `wujie()`                                                       | true              | 子应用渲染模式：true=wujie 微前端 /false = 传统 iframe      |
| `dataRoots()` / `sqlRoots()` / `seedData()` / `schemaVersion()` | 继承自 SoysExpansion | 数据初始化（见 05 - 数据与初始化）                           |
| `resourceRoot()` / `indexFallbackEnabled()` / `spaFallback()`   | 继承自 SoysExpansion | 页面托管                                           |

## 3. 菜单 DSL（`ErpMenus`）

方法名定节点类型：`dir`=M 目录、`menu`=C 菜单、`perm`=F 按钮权限、`route`=path→component 便捷 C 菜单。

### 3.1 lambda 嵌套（推荐，最接近 YAML 缩进）



```
return ErpMenus.create()

    .dir("system", "系统管理", "system", d -> d        // 目录，lambda 内为子级

        .menu("user", "用户列表", "user")              // 叶子菜单

            .perm("soys.erp.user.list")               // 按钮（挂到当前层级）

            .perm("soys.erp.user.add")

        .menu("group", "权限组列表", "lock"))

    .menu("home", "首页", "home").component("erp/home"); // 顶层叶子
```

### 3.2 流式 + up ()



```
return ErpMenus.create()

    .dir("system", "系统管理", "system")   // 进入子级上下文

        .menu("user", "用户列表", "user")

        .menu("group", "权限组列表", "lock")

    .up()                                 // 返回上一级

    .menu("home", "首页", "home").component("erp/home");
```

### 3.3 全属性 spec（所有表字段一次填齐）



```
return ErpMenus.create()

    .dir(s -> s.menuId("system").menuName("系统管理").icon("system").orderNum(1), d -> d

        .menu(m -> m.menuId("user").menuName("用户列表").icon("user")

            .perms("soys.erp.user.list").orderNum(10).component("erp/user").visible(true))

        .perm(p -> p.menuId("user:add").menuName("新增用户").perms("soys.erp.user.add")))

    .route("stock/io", "erp/io").perms("stock:io:list");
```

`MenuSpec` 支持全部表字段：`menuId/menuName/parentId/orderNum/path/component/componentFull/componentFullURL/`

`query/routeName/isFrame/isCache/menuType/visible/status/perms/icon/builtin`。

### 3.4 component 免写（自动拼接）



* `component("erp/user")` → 自动拼 `pageDirRoot()` = `/web/plugins/<模块ID>/<安全目录名>/erp/user`；

* `componentFull("xxx")` → 只补 `/web/plugins/<模块ID>`；

* `componentFullURL("https://example.com/page")` → 不拼任何前缀（外链）；

* **完全不写 component**：C 菜单按 `basePrefix + 父级 dir 链 + "/" + menuId` 自动拼接

  （如 `dir("config") > dir("dict") > menu("type")` → `/web/plugins/<id>/<安全名>/config/dict/type`）。

## 4. 自动按钮（Controller → F 按钮）

菜单下的按钮无需手写：给 `menu()` 传入 controller 类，或链式 `permsFrom(Class...)`，

`ControllerPermScanner` 会按下列规则自动把端点方法投影为 F 按钮：



| 规则        | 行为                                                                           |
| --------- | ---------------------------------------------------------------------------- |
| 端点判定      | 方法上存在 `@GetMapping/@PostMapping/@PutMapping/@DeleteMapping` 之一               |
| 按钮名       | 方法级 `@ApiName` → 类级 `@ApiName` → Java 方法名                                    |
| 权限        | 方法级 `@ApiPermission` → 类级 `@ApiPermission`；`@ApiPublic`（方法级或类级）时按钮不设权限（登录即可） |
| 默认拒绝端点    | 既无 `@ApiPermission` 又无 `@ApiPublic`（网关默认 403）→ 不生成按钮                         |
| `@Hidden` | 方法级或类级 → 跳过，不生成按钮                                                            |
| menuId    | 有权限用权限串；`@ApiPublic` 无权限用 Java 方法名                                           |
| 排序        | 按方法声明顺序递增                                                                    |



```
return ErpMenus.create()

    .dir("system", "系统管理", "system", d -> d

        .menu("user", "用户列表", "user", ErpUserController.class) // 按钮自动生成

        .menu("group", "权限组列表", "lock").permsFrom(ErpGroupController.class))

    .menu("home", "首页", "home").component("erp/home");
```

## 5. 生命周期与索引重建



* **登记**：`McerpExpansion.onRegister()`（SoysExpansion 注册骨架回调）→ 写入 `ErpRegistry` 索引；

* **摘除**：`onUnregister()` / 插件禁用（`PluginDisableEvent`）→ 移除索引，卸载同步清理；

* **判定**：`instanceof McerpExpansion`（宿主 `McErpHostExpansion` 是 `SoysExpansion` 直系子类，天然排除）；

* **兜底重建**：`/mcerp reload` 与 `/soyshttp reload`（`registerReloadHook`）以及服务器完全启动后的一次扫描，

  都会以 `SoysExpansion.REGISTERED` 为准清理残留索引并补登记。

## 6. 页面托管与微前端



* 附属插件的静态资源放在 `resources/dist/`，经 `resourceRoot()` 声明由主插件托管于 `/web/plugins/<模块ID>/`；

* 菜单默认以 **wujie（无界微前端）** 模式嵌入 MCERP 主应用（`wujie()` 返回 true）：

  子应用需配合 history 路由 + 绝对 publicPath + 空 Layout（不渲染自己的登录页与侧边栏）；

* 若 `wujie()` 返回 false，则退回传统 iframe 模式。

> 详见 06 - 前端定制与微前端。

## 7. 插件自带图标（教程）

MCERP 的侧边栏由宿主自己渲染，子应用的 `SvgIcon` 不参与，因此**图标资源必须能被宿主直接取到**：

要么用宿主内置 sprite 的名字，要么给出宿主同源可访问的图片地址，要么通过 `icons/manifest.json`

把 “逻辑名” 交给宿主解析。本节按 “放资源 → 写 manifest → 菜单引用 → 自检” 的顺序走一遍。

### 7.1 三种写法怎么选



| 写法          | 例子                                 | 渲染                                   | 适用                 |
| ----------- | ---------------------------------- | ------------------------------------ | ------------------ |
| sprite 名    | `system`、`user`                    | `<svg><use href="#icon-…">`，单色，跟随主题  | 宿主已内置的通用图标         |
| 同源图片路径      | `/web/plugins/stock/icons/box.png` | `<img>` 原色，不做 mask 染色                | 已有 png/svg 成品，路径固定 |
| `img:<key>` | `img:pack`                         | 先查本插件 `icons/manifest.json`，命中后按图片渲染 | 图标多、想用逻辑名解耦文件名     |

三条铁律：



* 纯名字必须存在于宿主 `src/assets/icons/svg/`，否则空白；

* 图片路径只接受**单个&#x20;**`/`**&#x20;开头的同源路径**，扩展名限 `png/jpg/jpeg/gif/webp/svg/ico/bmp/avif`，可带 query；

* `img:` 只是逻辑名，解析失败会保留原值，最终由宿主回退为 `form` 图标，不会留空白。

### 7.2 第一步：把图标放进插件静态根

图标放在附属插件的 `src/main/resources/dist/icons/`，随 `resourceRoot()` 一起托管到

`/web/plugins/<模块ID>/icons/`。建议 16×16 或 32×32 的 png（侧边栏按 `1em` 渲染，像素图会启用

`image-rendering: pixelated` 保持清晰）。



```
dist/
├── icons/
│   ├── gift.png
│   ├── light_blue_bundle.png
│   └── manifest.json
└── index.html
```

### 7.3 第二步：写 `icons/manifest.json`



```
{
  "version": 1,
  "icons": {
    "gift": "icons/gift.png",
    "pack": "icons/light_blue_bundle.png"
  }
}
```



* 值可以是相对插件根的路径（推荐），也可以是 `/web/plugins/<id>/...` 绝对路径；

* 含 `..`、或绝对路径不以 `/web/plugins/` 开头的值会被宿主拒绝；

* `version` 目前只做标记，不参与解析；

* 宿主只在**子树里真的出现&#x20;**`img:` 时才拉取该插件的 manifest；全部用 sprite 或直接图片路径时零请求，不增加登录耗时。

### 7.4 第三步：在菜单里引用

`ErpMenus` 的 `dir/menu/route` 第三个参数就是图标：



```
@Override
protected ErpMenus menus() {
    return ErpMenus.create()
        .dir("loot", "战利品配置", "img:gift", d -> d
            .menu("reward", "礼包列表", "img:pack")
            .menu("monster", "怪物配置", "bug")
            .menu("claim", "领取记录", "form"))
        .menu("config", "插件配置", "edit");
}
```

模块自身的图标走 `icon()` 钩子（默认 `null`，宿主会退成 `link`，不是空白）：



```
@Override
protected String icon() {
    return "img:gift";
}
```

### 7.5 宿主是怎么解析的



1. 登录后 `GET /auth/getRouters` 拿到菜单树；

2. `store/modules/permission.js` 在 `filterAsyncRouter` 之前调用 `resolveMenuIcons`；

3. `utils/pluginIcons.js` 先扫出 “子树里含 `img:` 的插件”，并行 `GET /web/plugins/<id>/icons/manifest.json`

   （`credentials: same-origin`、`cache: force-cache`、3 秒超时、失败静默、结果进双 Map 缓存）；

4. 归属判定：先看节点 `component`（`wujie:/web/plugins/<id>/…` 或 `iframe:…`）；父节点自身没有组件时，

   取子树内唯一的插件 id；

5. 命中后把 `meta.icon` 就地改写成 `/web/plugins/<id>/icons/xxx.png`，再交给路由过滤器；

6. `SvgIcon` 按 `isImage` 走 `<img>`，否则走 sprite；图片 `error` 时复位的 `effectiveIcon` 回退 `form`。

### 7.6 自检清单



```
# 1) manifest 可访问且是 JSON（静态服务不支持 HEAD，必须用 GET）
curl -s -o /dev/null -w "%{http_code} %{content_type}\n" \
  https://<host>/web/plugins/<模块ID>/icons/manifest.json

# 2) 图标本体可访问
curl -s -o /dev/null -w "%{http_code} %{content_type} %{size_download}\n" \
  https://<host>/web/plugins/<模块ID>/icons/light_blue_bundle.png
```



* 两个请求都应是 `200`；图标响应通常带 `Cache-Control: public, max-age=300`；

* 登录后看菜单项：`img:` 应已被替换成 `/web/plugins/...` 图片地址；

* 换图后不生效，先强制刷新（`Ctrl+F5`）或换新文件名，`manifest` 也要等缓存过期后才会重新拉取；

* 侧边栏空白而接口正常时，优先核对 “名字是否在 sprite 里 / 路径是否符合同源白名单”。

### 7.7 常见问题



| 现象           | 原因                                       | 处理                                |
| ------------ | ---------------------------------------- | --------------------------------- |
| 菜单图标空白       | 名字不在宿主 sprite；或图片路径不符白名单                 | 改用 `img:<key>` 或合规的同源路径           |
| `img:` 一直不生效 | manifest 404 / JSON 字段不是 `icons` /key 拼错 | 用上面的 curl 自检，确认 `{"icons":{...}}` |
| 图片显示但颜色被改    | 走了 sprite 的 mask 分支                      | 用图片路径或 `img:`，不要写纯名字              |
| 图标模糊         | 原图尺寸与 `1em` 不匹配                          | 提供 16×16 / 32×32 素材               |
| 卸载插件后仍有图标    | 浏览器缓存了图片                                 | 属预期，换文件名或清缓存                      |

> 权限相关：菜单是否出现还取决于当前凭证能否通过 
>
> `hasPermission`
>
> 。OP 判定已按名字忽略大小写，
> 非 OP 用户的权限组仍由 SOYS 核心按 UUID 判定，详见 07 - 日志与运维的排障表。
