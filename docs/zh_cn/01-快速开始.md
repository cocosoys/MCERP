# 01・快速开始

本文介绍从零部署 MCERP 的完整步骤：环境要求、后端构建、前端构建、部署与访问。

## 1. 环境要求



| 项   | 要求                                                                    |
| --- | --------------------------------------------------------------------- |
| 服务端 | Spigot 1.12.2（CraftBukkit 1.12.2-R0.1-SNAPSHOT）                       |
| 主插件 | SOYSHTTPOverMC ≥ 1.4.0（`depend: [SOYSHTTPOverMC]`，必须先在 `plugins/` 就位） |
| JDK | 8                                                                     |
| 构建  | Maven 3.x（后端）；Node.js + npm（前端，可选）                                    |

> MCERP 通过 
>
> `pom.xml`
>
>  的 
>
> `systemPath`
>
>  直接引用主插件构建产物：
> `../SOYSHTTPOverMC/core/target/SOYSHTTPOverMC-1_12-1.4.0.jar`
>
> 。
> 因此
>
> **主插件源码需要与 MCERP 同级目录**
>
> （均为 
>
> `plugins/spigot/1.12.2/`
>
>  下），且主插件 jar 需已构建。

## 2. 后端构建



```
cd D:\WorkTools\Project\Minecraft\plugins\spigot\1.12.2\MCERP

mvn -o clean package -DskipTests
```

> ⚠️ 务必使用 
>
> `clean`
>
> 。本项目遇到过 Maven 增量编译复用历史坏 class 的问题
> （源文件未变时跳过重编，导致运行时 
>
> `log cannot be resolved`
>
>  之类的错误），
> `clean`
>
>  全量重建可彻底规避。

产物：`target/MCERP-1.0-SNAPSHOT.jar`。

## 3. 前端构建（可选，仅在修改前端后需要）

前端工程位于 `RuoYi-Vue2-master/`（基于 RuoYi-Vue2 定制）：



```
cd RuoYi-Vue2-master

npm install          # 首次

npm run build:prod   # 生产构建
```

构建产物在 `dist/`，需要**全量同步**到后端资源目录：



```
Copy-Item dist\\\* ..\src\main\resources\dist\ -Recurse -Force
```

然后重新执行第 2 步后端构建，把新前端打进 jar。

> `dist/`
>
>  中必须包含 
>
> `__SOYS_CONTEXT__.js`
>
> —— 这是主插件 ContractInjector 自动契约文件，
> 负责在伺服时把前端用到的 apiBase / 页面前缀 /host/port 占位符替换为服务器环境原语，
> 前端代码里不写死任何地址。

## 4. 部署



1. 复制 jar 到服务端插件目录：



```
Copy-Item target\MCERP-1.0-SNAPSHOT.jar D:\MyGame\Minecraft\Server\Spigot\1.12.2\plugins\ -Force
```



1. 重启服务器（停止旧进程后重新启动）：



```
\# 停止占用 25565 的旧进程

Get-NetTCPConnection -LocalPort 25565 -State Listen | Stop-Process -Id { $\_.OwningProcess } -Force

\# 重新启动

Start-Process D:\WorkTools\JDK\8\bin\java.exe -WorkingDirectory D:\MyGame\Minecraft\Server\Spigot\1.12.2 \`

&#x20; -ArgumentList "-Xmx2G","-jar","Spigot-1.12.2-build1573k.jar","nogui"
```



1. 验证启动：端口 25565 开始监听，`logs/latest.log` 中应能看到：



```
\[MCERP] SOYS 接入完成：SoysExpansion 门户注册（路由） + dist 托管（expansion:MCERP）

\[MCERP] 已启用 (ERP 统一中控)

\[MCERP] ERP 模块已登记: <附属模块标识>
```

## 5. 访问



* 测试入口：`https://localhost:25565/web/plugins/MCERP/index`

* 生产（换服务器）：`https://<host>:<port>/web/plugins/MCERP/index`

> 服务端为 HTTPS 自签证书，浏览器会提示证书不受信任，选择继续访问即可。

首次打开会进入登录页。登录链路完全由主插件 auth 提供（`/api/auth/login`）：



* 未安装 AuthMe 时：输入任意合法玩家名（字母 / 数字 / 下划线，≤16 字符）即可免密码登录；

* 安装了 AuthMe：需要玩家名 + AuthMe 密码。

## 6. 常用命令



| 命令                               | 说明                                                        |
| -------------------------------- | --------------------------------------------------------- |
| `/mcerp reload`（或 `/erp reload`） | 重建 ERP 模块索引：以主插件 `SoysExpansion.REGISTERED` 为准，清理残留索引并补登记 |
| `/mcerp list`（或 `/erp list`）     | 列出当前已登记的 ERP 模块（标识 + 显示名）                                 |

需要权限 `mcerp.admin`（默认 OP）。

## 7. 常见问题



| 现象                                           | 原因 / 解决                                                                         |
| -------------------------------------------- | ------------------------------------------------------------------------------- |
| 打开页面 404                                     | 前端未打进 jar，或 `dist/` 缺少 `__SOYS_CONTEXT__.js`；重新构建并同步 dist                       |
| 接口 404                                       | 确认请求路径带完整前缀 `/api/plugins/MCERP/...`；路由无尾斜杠（`/system/user` 而非 `/system/user/`）  |
| 被强制跳到登录页                                     | 主插件 auth 未启用会话令牌颁发器；检查主插件 `gateway/issuers/session-token.yml` 的 `enabled: true` |
| 页面打不开、控制台 `Maximum call stack size exceeded` | 前端 `dist` 与后端契约不匹配（通常为旧版本前端）；重新构建前端并同步                                          |
